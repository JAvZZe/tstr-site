# tstr.directory Scraper Failure Monitor

This script monitors the scraper logs for failures and alerts when errors are detected.

## Files

- `monitor_scraper.py` - Main monitoring script
- `scraper.log` - Log file generated by the scraper (created by run_scraper.py)
- `scraper_alerts.log` - Alert log file generated by this monitor

## How It Works

The monitor checks the scraper.log file for error patterns from the last N hours (configurable via SCRAPER_MONITOR_CHECK_HOURS environment variable, defaults to 2 hours).

When errors are detected:
1. Logs the errors to the console and to scraper_alerts.log
2. Returns exit code 1 (indicating errors found)
3. If no errors are found, returns exit code 0

## Error Patterns Detected

The monitor looks for these patterns in the log files:
- CRON JOB FAILED
- Exception.*scraper.*failed
- Error.*scraper
- failed.*scraper
- Traceback.*most recent call last
- APIError:
- ValidationError:
- ConnectionError
- TimeoutError
- HTTP.*Error
- JSON.*could not be generated
- Invalid API key
- Authentication failed
- Permission denied
- Exited with code.*[1-9] (non-zero exit codes)

## Usage

### Manual Testing
```bash
python3 monitor_scraper.py
echo "Exit code: $?"
```

### Automated Monitoring (Cron Job)
Add to crontab to run after the main scraper completes:

```bash
# Run scraper monitor 5 minutes after main scraper (adjust timing as needed)
5 2 * * * cd /media/al/AI_DATA/AI_PROJECTS_SPACE/ACTIVE_PROJECTS/tstr-site-working/web/tstr-automation && /usr/bin/python3 monitor_scraper.py
```

Or to chain it with the scraper (run monitor immediately after scraper):
```bash
# In your crontab, modify the scraper job to:
0 2 * * * cd /media/al/AI_DATA/AI_PROJECTS_SPACE/ACTIVE_PROJECTS/tstr-site-working/web/tstr-automation && /usr/bin/python3 run_scraper.py && /usr/bin/python3 monitor_scraper.py
```

### Environment Variables
- `SCRAPER_MONITOR_CHECK_HOURS` - How many hours back to check for errors (default: 2)
- `ALERT_EMAIL_ENABLED` - Set to 'true' to enable email alerts (requires SMTP config)
- SMTP variables (if email alerts enabled):
  - `SMTP_SERVER`
  - `SMTP_PORT`
  - `SMTP_USERNAME`
  - `SMTP_PASSWORD`
  - `ALERT_FROM`
  - `ALERT_TO`

## Integration with Existing Systems

This monitor is designed to work with the existing scraper infrastructure:
- The main scraper (`run_scraper.py`) creates `scraper.log` in the same directory
- The monitor reads this log file and detects failures
- Can be run as a separate cron job or chained with the scraper

## Log Files

- `scraper.log` - Generated by run_scraper.py, contains scraper output
- `scraper_alerts.log` - Generated by this monitor, contains alerts and monitoring output
